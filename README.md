# FCアガペ チームノート（本番反映前）

対象ブランチは claude/day09-neo。main は使用しません。

## 使い方

- メイン：index.html または team.html。Googleログインのメールと登録名簿を自動照合し、本人の出欠を直接表示します。名前選択はありません。
- ジュニア：team.html#team=<共有鍵>。ログイン不要。縦並びの名簿から各参加者の出欠を変更します。
- 管理：team.html#admin=<既存管理鍵>。名簿のメール登録、予定、会計、設定、代理回答ができます。
- 車は「車の利用予定は？」。利用する場合はナンバー全体を入力し、次回は前回値を表示します。
- 助っ人は各予定の「誰が来る？」からゲスト追加。メインでは追加者を自動記録します。

詳細は requirements.md。旧個人トークン・招待コードによる回答APIは閉じています。

## 安全なローカル確認

1. npm install
2. npm test
3. npm run preview:test

テストは使い捨てのメモリ内PostgreSQL（PGlite）のみ。本番接続・データ削除はありません。
26件のテスト結果に旧33 SQLチェックも含みます。旧実ブラウザ17件は新画面とは異なり、このコマンドには含みません。
プレビューは127.0.0.1:8173。通常の team.html はログイン案内、team.html?preview=main は仮ログイン、#team=bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb はジュニア、#admin=aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa は管理画面です。
仮ログインはテストサーバーだけが提供するもので、本番のGoogle OAuthを検証したことにはなりません。テスト用認証スクリプトは公開されません。

## 本番への適用（承認後）

1. バックアップと変更承認を確認。
2. npm run migration で work/migration.sql を生成（生成だけで実行しません）。
3. Supabase SQL Editorで生成SQLを同一トランザクションとして適用。schema.sql → team.sql → access.sql の順です。個別のschema.sqlだけを再適用すると旧権限が復活するため、必ず生成SQL全体を使用します。
4. Google OAuthの認証設定と team.html へのリダイレクト許可を確認。Googleアプリの公開問題が続く場合はテストユーザー登録を確認。
5. claude/day09-neoへpushしてNetlifyで公開。環境変数 SUPABASE_URL / SUPABASE_ANON_KEY は既存の設定を使用。秘密キーは使いません。
6. 管理画面のメイン名簿に各人のGoogleメールを登録。実アカウントでログイン→本人回答→再読込を確認。
7. メインへ通常URL、ジュニアへ設定からコピーした共有URLを配布。

SQLは既存データを削除しません。旧index.htmlは新画面へ移動します。旧管理画面admin.htmlは管理鍵の入口として残していますが、新しい運用はチームノート管理画面を使用してください。
ブラウザの実行時ライブラリは追加していません。npmのビルドは公開可能な静的ファイルと設定だけをdistへ取り出します。
