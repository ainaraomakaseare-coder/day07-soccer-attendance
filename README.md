# サッカー出欠管理

チームの出欠を、スプレッドシートの代わりに管理するアプリです。マネージャーが予定を登録し、メンバーは**LINEで配られた自分専用のリンク**を開いて出席か欠席かを1タップで答えます。

**一度 Google でログインすれば、次からはリンクを探す必要がありません。**

**入力した内容はデータベースに残ります。**アプリを閉じても、別の端末から開いても、消えません。

```
managerが予定をつくる  →  LINEで個人リンクを配る  →  各自が1タップで回答
                                                   ↓
                                    出席人数と「未回答の人」が一覧で見える
```

## 画面は2つだけ

| ファイル | 誰が使う | 開き方 |
|---|---|---|
| `index.html` | メンバー | `.../#<個人トークン>` |
| `admin.html` | マネージャー | `.../admin.html#<管理トークン>` |

ログイン画面はありません。**リンクそのものが鍵**です。だから、LINEでURLを踏んだ人はそのまま自分の欄だけ触れます。

---

## 用意するもの

- Supabase のアカウント（無料）
- **Node.js** … [nodejs.org](https://nodejs.org/ja) から LTS 版を入れてください。
  入れたあとは**ターミナル（コマンドプロンプト）を一度閉じて開き直します。**
  開き直さないと `npm` が「認識されていません」と言われ続けます。

入っているか確かめるには：

```
node -v
npm -v
```

どちらもバージョン番号（`v22.x.x` のような文字）が出れば大丈夫です。

費用は **0円** です。Supabase の無料枠（データベース500MB・通信5GB/月）に対して、30人×年間100予定でも1MBに届きません。

> **注意：** 無料プランは**1週間まったくアクセスが無いとプロジェクトが一時停止します。**データは消えず、管理画面のワンクリックで戻ります。オフシーズンで間が空いたときだけ気をつけてください。

## 準備の手順

### 1. Supabase でプロジェクトを作る

[supabase.com](https://supabase.com) でプロジェクトを1つ作ります。リージョンは Tokyo が近くて速いです。

### 2. データベースの中身を作る

左メニューの **SQL Editor** を開き、このリポジトリの **`db/schema.sql` の中身を丸ごと貼り付けて Run** を押します。

実行が終わると、いちばん下に**管理用トークン**（32文字の英数字）が表示されます。**これをメモしてください。**あなただけの管理画面の鍵です。人に見せないでください。

> 見失っても大丈夫です。SQL Editor で `select admin_token from team_config;` を実行すればまた見られます。

### 3. 接続情報を手元に置く

Supabase の **Project Settings → API** を開き、2つの値をコピーします。

- **Project URL**
- **公開してよい方のキー**

キーの呼び方は Supabase のプロジェクトによって2通りあります。**どちらでも動きます。**

| | 使う（公開してよい） | 使わない（秘密） |
|---|---|---|
| 古い呼び方 | `anon` `public` | `service_role` |
| 新しい呼び方 | `sb_publishable_…` | `sb_secret_…` |

間違えて秘密の方を書いた場合は `npm run setup` が止めます。

そして手元でこうします。**見本から自分用のファイルを作ります。**

Mac / Linux：

```bash
cp .env.example .env
```

Windows（コマンドプロンプト）：

```
copy .env.example .env
```

> Windows には `cp` がありません。`copy` です。
> また、コマンドの後ろに `# ...` のような説明を付けたまま貼り付けると失敗します。コマンドだけを貼ってください。

`.env` を**メモ帳などで開いて**、コピーした値を書きます。

```
SUPABASE_URL=https://xxxxxxxx.supabase.co
SUPABASE_ANON_KEY=sb_publishable_...
```

> **URL の末尾に注意。** Supabase の Data API のページは URL を
> `https://xxxxxxxx.supabase.co/rest/v1/` の形で表示します。
> このアプリは `/rest/v1/...` を自分で付け足すので、**`/rest/v1/` は要りません**。
> 付けたまま貼っても `npm run setup` が外してくれますが、そのとき一言表示されます。

> **秘密の方のキー（`service_role` / `sb_secret_…`）は絶対に使わないでください。**あれは全ての安全装置を無視できるマスターキーです。このアプリでは一切使いません。間違えて書いた場合は次のステップで止まるようにしてあります。

### 3-b. Google ログインを使えるようにする

ログイン無しでも動きますが、使うならこの3つが要ります。**この順番**でやってください。
Netlify の住所が決まらないと Supabase の設定が終わらないためです。

1. **公開先の住所を決める**（下の「インターネットに公開する」を先に済ませる）
2. **Google Cloud Console** でプロジェクトを作り、
   **APIとサービス → OAuth同意画面** を設定して**「本番」に公開**する
   （「テスト中」のままだと、メンバーを1人ずつテストユーザーに登録する必要があります。
   使うのはメールアドレスと名前だけなので、審査は要りません）
   → **認証情報 → OAuth クライアント ID → ウェブアプリケーション**を作り、
   承認済みリダイレクト URI に `https://<プロジェクトID>.supabase.co/auth/v1/callback` を入れる
3. **Supabase** → Authentication → Sign In / Providers → Google を有効にして、
   クライアントIDとシークレットを貼る。
   さらに URL Configuration の Site URL と Redirect URLs に、公開先の住所を入れる

> **クライアントシークレットは Supabase の画面に貼るだけです。**
> `.env` にもリポジトリにも書きません。

### 4. 起動する

Mac / Linux / Windows 共通です。

```
npm start
```

`npm start` が `.env` を読み込んで起動まで済ませます（`npm run setup` は単体で確認したいとき用）。
このアプリは追加のライブラリを使っていないので、`npm install` は要りません。

うまくいくと、こう出ます。

```
config.local.js を作りました。
  接続先: https://xxxxxxxx.supabase.co
  キー  : eyJhbGci…（以降は伏せます）

  出欠アプリを開きました
  管理画面 : http://localhost:8000/admin.html#<管理用トークン>
  メンバー : http://localhost:8000/#<個人トークン>
```

止めるときは `Ctrl+C` です。

ブラウザで `http://localhost:8000/admin.html#<手順2でメモした管理トークン>` を開けば管理画面です。

### 5. 使いはじめる

1. **メンバー**タブで、今のスプレッドシートから名前をコピーして貼り付け →「まとめて登録」
2. **予定**タブで、日付と場所を入れて予定を追加
3. **リンク配布**タブで「全員分をコピー」→ チームのLINEに貼る

## 接続情報を、何をどこに置いたか

ここが一番事故りやすいところなので、置き場所をはっきりさせておきます。

| 物 | 置き場所 | GitHubに上がるか |
|---|---|---|
| Project URL・anon キーの**実物** | `.env` | **上がりません**（`.gitignore` 済み） |
| そこから作られる `config.local.js` | 手元だけ | **上がりません**（`.gitignore` 済み） |
| 書き方の**見本**（値は空） | `.env.example` / `config.example.js` | 上がります（安全） |
| `service_role` キー | **どこにも置きません** | — |

### anon キーはブラウザに出ます。それでいいのか

出ます。そして**それで問題ありません。** anon キーは、Supabase が「ブラウザに配る前提」で設計しているキーだからです。

守っているのはキーの秘密ではなく、**データベース側の鍵**です。このアプリでは全テーブルで RLS（行レベルセキュリティ）を有効にし、**許可ルールをひとつも書いていません**。つまり anon キーを持っていても、テーブルは何ひとつ読めず、書けません。

読み書きはすべて `db/schema.sql` の下半分にある**関数だけを窓口**にして通ります。関数は毎回トークンを確かめてから動きます。だから、

- リンクを持っていない人 → 何も見えない
- 自分のリンクを持っている人 → **自分の欄だけ**動かせる
- 管理トークンを持っている人 → 名簿と予定を触れる

この「テーブルに鍵をかけて、窓口だけ開ける」という形が、このアプリのいちばん大事な設計です。

### ログインすると何が変わるか

招待リンクは**一度きりの招待状**です。

| | ログイン前 | ログイン後 |
|---|---|---|
| 入り方 | 招待リンクを開く | ページを開くだけ |
| 本人確認 | リンクを持っていること | Google アカウント |
| リンクを転送されたら | **その人になりすませる** | 古いリンクは**使えない** |

1. メンバーが LINE の招待リンクを開く
2. 「Googleでログイン」を押す
3. その Google アカウントと名簿の本人が結びつく
4. 以後は素の URL を開くだけ。**ログインし直しは要りません**（セッションは無期限）

**まだログインしていない人の招待リンクは、今までどおり使えます。**全員が一斉にログインするのを
待たずに移行できます。誰がログイン済みかは、管理画面の「メンバー」タブで分かります。

> **LINE の内蔵ブラウザ対策。** LINE の中のブラウザは Google 認証を弾きます（`403: disallowed_useragent`）。
> そのため配布する招待リンクには `?openExternalBrowser=1` が付いていて、
> LINE が端末の既定ブラウザ（iPhone は Safari、Android は Chrome）で開いてくれます。

### 自分の名前を変える

ログインしていれば、画面右上の「名前を変える」から自分の表示名を直せます。
実名で運用するので、表記のゆれ（「山本 陸」／「山本陸」）は本人が直せた方が早いためです。

### 管理リンクが漏れたら

管理画面の**リンク配布**タブのいちばん下、「管理リンクを作り直す」を押してください。
古い管理リンクはその場で使えなくなり、新しいURLがアドレス欄に入ります。ブックマークを取り直してください。

### リンクが漏れたら

管理画面の**リンク配布**タブにある「作り直す」を押してください。その人の合言葉が変わり、**古いリンクはその場で使えなくなります。**新しいリンクを渡し直してください。

## テスト

```bash
npm test
```

これで下の2つをまとめて走らせます。足りないものがあれば、何を用意すればいいか案内が出ます。

### データベースの動きと鍵のかかり具合

```bash
psql -v ON_ERROR_STOP=1 -d <データベース> -f test/db.test.sql
```

25項目を確かめます。特に大事なのは中盤で、**わざと anon にテーブルの読み書き権限を与えた上で、それでも何も見えないこと**を確認しています。守っているのが権限ではなく RLS だと分かるようにするためです。

後半の8項目はログインまわりです。使い終わった招待リンクが通らないこと、他人が同じ招待リンクを
使えないこと、管理トークンを作り直すと古いものがその場で無効になることを確かめています。

手元の PostgreSQL には Supabase の `auth.uid()` が無いので、テストが同じ名前の代役を用意します。

### 画面の通し確認

実ブラウザで、予定作成 → 回答 → **閉じて開き直しても残っていること** → 別端末から見ても残っていることまで通します。`npm test` がサーバーの起動と後片付けまでやります（Windows / Mac / Linux 共通）。

個別に走らせたい場合：

```bash
node test/fake-supabase.js &   # Supabase の代役（手元の PostgreSQL に繋ぐ）
node scripts/serve.js &
node test/ui.smoke.js
```

`test/fake-supabase.js` はテスト専用です。本番では使いません。

## インターネットに公開する（LINEでリンクを配るために必要）

手元で `npm start` しただけでは、そのURLは**自分のパソコンの中だけ**の住所です。LINEで投げても他の人は開けません。みんなに見てもらうには、どこかに置いて公開する必要があります。

### 公開してよいファイルだけを取り出す

まず、これを実行します（Windows も同じ）。

```
npm run build
```

`dist/` というフォルダができ、**公開してよい4つのファイルだけ**がそこに入ります。

```
dist/index.html
dist/admin.html
dist/js/db.js
dist/config.local.js
```

**`.env` は入りません。** フォルダをまるごとアップロードすると接続情報まで公開してしまうので、それを防ぐための仕組みです。`service_role` が混ざっていた場合もここで止まります。

> 実行する前に、`.env` に**本物の** Supabase の URL とキーが入っていることを確認してください。テスト用の値のままだと、公開したアプリが動きません。

### 置き場所（無料）

いちばん手軽なのは **Netlify** です。アカウントを作り、[app.netlify.com/drop](https://app.netlify.com/drop) に **`dist` フォルダをドラッグ＆ドロップ**するだけで、`https://○○○.netlify.app` という住所がもらえます。GitHub のリポジトリは要りません。

GitHub と繋いで「push したら自動で公開」にしたい場合は、`netlify.toml` を用意してあります。Netlify の管理画面の **Environment variables** に `SUPABASE_URL` と `SUPABASE_ANON_KEY` を登録してください。公開のたびにそこから読み取って `config.local.js` を作るので、**接続情報を GitHub に置く必要はありません。**

> **Netlify の鍵検査に引っかかります。** Netlify には「環境変数の値が公開ファイルに出てきたら
> 流出とみなしてビルドを止める」仕組みがあります。このアプリは anon キーを**意図的に**
> ブラウザへ配るので、そのままだと必ず止まります。
> `netlify.toml` の `SECRETS_SCAN_OMIT_KEYS` で、この2つだけ見逃すようにしてあります。
> （守っているのは鍵の秘密ではなく RLS です。上の「anon キーはブラウザに出ます」を参照）

### 公開したら、最後にひとつ

管理画面の**リンク配布**タブを開き、いちばん上の「公開先のURL」に、もらった住所（`https://○○○.netlify.app`）を入れて保存してください。個人リンクがその住所で作られるようになります。

そのあと「全員分をコピー」を押して、チームのLINEに貼れば完了です。

## いま出来ないこと

- **出欠は「出席・欠席・未回答」の3つだけ**です。「未定」「遅刻」を足すことはできますが、今は入れていません。
- **まだログインしていない人のリンクは、転送されるとなりすませます。**ログインを済ませた人については、古いリンクは使えなくなります。全員にログインしてもらうのが確実です。
- **公開の作業自体は手動です。**`npm run build` して `dist` を置き場所にアップロードする、という手順を踏みます。自動化はしていません。
